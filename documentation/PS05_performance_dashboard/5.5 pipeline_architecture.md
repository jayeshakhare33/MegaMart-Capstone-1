## 2. Layer Architecture

### 2.1 Bronze Layer (Raw)

- **Purpose**: Store raw CSV data as-is with minimal transformation.
- **Tables** (6): `stores_raw`, `products_raw`, `suppliers_raw`,
  `sales_transactions_raw`, `inventory_raw`, `purchase_orders_raw`
- **Location**: `megamart_dev.bronze`
- **Source**: CSV files in Unity Catalog Volume `megamart_dev.bronze.raw_files`
- **Script**: `01_ingestion/01_ingest_raw.py`
- **Table type**: MANAGED Delta tables

### 2.2 Silver Layer (Cleaned & Modeled)

- **Purpose**: Clean, type-cast, and model data for analytics.
- **Tables** (6): `stores`, `products`, `suppliers`, `sales_transactions`,
  `inventory`, `purchase_orders`
- **Location**: `megamart_dev.silver`
- **Script**: `03_model/03_build_silver.py`
- **Key transformations**:
  - Date parsing (`transaction_date` → DATE type)
  - Numeric type casting (`quantity` → INT, `unit_price` → DECIMAL)
  - Phone number normalization
  - Data quality flag columns
- **Data quality**: `02_quality/02_validate_clean` notebook validates and
  logs issues to `megamart_dev.audit.data_quality_issues`

### 2.3 Gold Layer (KPI Views)

- **Purpose**: Compute KPIs on demand from Silver — no stored data, no stale
  results.
- **Location**: `megamart_dev.gold`
- **Definition**: `03B_generate_views/gold_layer_views.sql`
- **Architecture decision**: 10 views replace 18 former physical tables. Views
  compute on demand from Silver, eliminating storage overhead and stale data.

#### Gold Views (10)

| View | Granularity | Rows | Purpose |
| --- | --- | --- | --- |
| `store_performance` | per store | 5 | Store-level KPIs, rankings, inventory health |
| `product_performance` | store × product | 70 | Product velocity, revenue share, stock status |
| `top_products` | per product | 5 | Top 5 products by quantity sold |
| `monthly_store_trends` | store × month | 60 | Per-store monthly sales with MoM change |
| `monthly_kpis` | per month | 12 | Chain-wide monthly KPIs with MoM change % |
| `category_kpis` | per category | 7 | Category revenue, rank, top-3 flag, share % |
| `enterprise_kpi` | single row | 1 | Chain-wide summary (revenue, transactions, inventory) |
| `inventory_status` | store × product | 70 | Stock status classification |
| `supplier_scorecard` | per supplier | 12 | Delivery reliability, lead time |
| `store_category_top3` | store × top-3 cat | 15 | Top 3 categories per store by revenue |

#### Gold Table (1)

| Table | Purpose |
| --- | --- |
| `reorder_recommendations` | Complex multi-step Python logic (safety stock, reorder points) — materialized for performance |

### 2.4 Audit Layer

- **Purpose**: Track pipeline runs and data quality issues.
- **Location**: `megamart_dev.audit`
- **Tables**:
  - `pipeline_runs` — one row per stage execution (run_id, status, timing, records)
  - `data_quality_issues` — per-record quality issues with severity and action

## 3. KPI Definitions

### 3.1 Metrics Calculated (Problem Statement 5.5.2)

| # | Metric | SQL Source | Computation |
| --- | --- | --- | --- |
| 33 | Total revenue by store | `store_performance.total_revenue` | `SUM(sales_transactions.total_amount)` per store |
| 34 | Average transaction value | `store_performance.average_transaction_value` | `SUM(total_amount) / COUNT(DISTINCT transaction_id)` per store |
| 35 | Unique products sold | `store_performance.unique_products_sold` | `COUNT(DISTINCT product_id)` per store |
| 36 | Inventory turnover ratio | `store_performance.inventory_turnover_ratio` | `total_quantity_sold / current_inventory_units` (simplified units-based proxy; status flag: `APPROXIMATE_UNITS_BASED_SINGLE_SNAPSHOT`) |
| 37 | Top 3 categories by sales | `store_category_top3` view | `ROW_NUMBER() OVER (PARTITION BY store_id ORDER BY category_revenue DESC)` filtered to rank ≤ 3 |
| 38 | Market share (% of chain) | `store_performance.market_share_pct` | `store_revenue / total_chain_revenue × 100` (internal chain share; status flag: `INTERNAL_CHAIN_SHARE`) |
| 39 | Year-over-month trend | `monthly_kpis` + `monthly_store_trends` | MoM revenue change % via `LAG()` window function |

### 3.2 Data Limitations Documented in Views

- **Inventory turnover**: The dataset has a single inventory snapshot and no
  COGS or average-inventory history. A simplified units-based ratio is
  provided with an explicit `inventory_turnover_status` flag.
- **Market share**: The dataset contains MegaMart sales only — no external
  market or competitor data. Internal chain share is provided with an
  explicit `market_share_status` flag.

## 4. Edge-Case Handling

| Edge Case | Handling |
| --- | --- |
| Division by zero | `NULLIF(denominator, 0)` in all ratio calculations |
| Missing data | `COALESCE(..., 0)` for zero-fill in counts and sums |
| Missing months | Calendar CTE with `CROSS JOIN` ensures complete Jan–Dec grid |
| NULL previous month | `LAG()` returns NULL for first month → MoM % set to NULL |
| Zero previous month | `CASE WHEN previous = 0 AND current > 0 THEN NULL` prevents infinite growth % |
| Decimal arithmetic | Spark DECIMAL → pandas `Decimal` → `.astype(float)` before chart math |
| Duplicate transactions | Verified in `verify_pipeline.py` (no duplicate `transaction_id` check) |
| Pipeline failure | `try/except` writes FAILED status to `audit.pipeline_runs` with error message |

- Volume: `megamart_dev.bronze.raw_files`

---

## 9. Reusability & Idempotency

- **Views**: `CREATE OR REPLACE VIEW` — re-running `gold_layer_views.sql`
  always produces the current state.
- **Tables**: `.mode("overwrite")` with `overwriteSchema` — safe to re-run.
- **Audit**: `.mode("append")` — accumulates run history.
- **Artifacts**: Each run gets a unique `RUN_ID` folder, so previous outputs
  are preserved.
